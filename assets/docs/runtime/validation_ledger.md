# Validation Ledger
Last updated: 2026-10-20

## Purpose and authority

The [project status ledger](../project_status_ledger.md) is the only current status catalog. Product behavior and ownership live in the architecture, runtime, coding, and user documents indexed in the [project index](../project_index.md).

This file keeps only cross-cutting validation findings, guarantees, and limits that help interpret those component statuses. It is organized by product concept, not by test date. Use [testing and quality](../coding/testing_and_quality.md) to run source gates and [desktop release](desktop_release.md) for packaged release gates.

## Evidence maintenance

Durable findings belong in the concept document linked above. Update the status ledger when a component status or limitation changes. Keep a dated QA report only when it provides evidence needed for a current external release or acceptance claim that cannot be represented by source documentation and repeatable gates. Local logs, screenshots, checklists, and run narratives are disposable unless the release record explicitly retains them.
